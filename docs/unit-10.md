# 10단원. 리스크관리·백테스트·RAG 통합 실습

## 학습 목표

시장·신용·유동성·운영·모형위험을 하나의 의사결정 체계에서 관리한다. 백테스트의 정보누수와 과최적화를 점검하고, RAG가 제시하는 답변을 근거 문서와 함께 검증한다.

## 위험은 숫자 하나가 아니다

**시장위험**은 금리, 주가, 환율, 변동성 변화로 인한 손실 가능성이다. **신용위험**은 거래상대방이나 발행자가 약속을 지키지 못할 위험이다. **유동성위험**은 자산을 적정 가격에 신속히 팔지 못하거나 필요한 자금을 조달하지 못할 위험이다. **운영위험**은 사람, 절차, 시스템, 외부 사건의 실패에서 발생한다. **모형위험**은 잘못된 가정·데이터·구현·사용으로 의사결정이 왜곡되는 위험이다.

위험 유형은 연결된다. 시장 급락으로 담보가치가 떨어지면 추가 증거금이 필요하고, 자금조달이 어려워지며, 급매로 시장충격이 확대될 수 있다. 따라서 위험을 부서별 숫자로만 분리하지 않고 공통 시나리오로 점검한다.

## VaR와 스트레스 테스트

VaR는 정해진 기간과 신뢰수준에서 정상적인 시장 조건 아래 예상되는 손실 경계를 추정한다. 예를 들어 1일 99% VaR가 1억 원이라는 말은 과거와 모형 가정이 유지될 때 하루 손실이 1억 원을 넘지 않을 확률을 99%로 추정했다는 뜻이다. 최대 손실이 1억 원이라는 의미가 아니다.

Expected Shortfall은 VaR를 초과한 꼬리 손실의 평균을 본다. 스트레스 테스트는 과거 위기나 가상의 극단 시나리오에서 손실, 유동성, 한도와 대응능력을 점검한다. 확률을 정밀하게 추정하기 어려운 사건도 시나리오로 다룰 수 있다.

## 한도와 모니터링

위험한도는 조직의 위험선호를 실제 업무 기준으로 바꾼다. 포지션, 민감도, VaR, 손실, 집중도, 유동성 한도를 함께 사용할 수 있다. 한도 초과 시 보고 대상, 승인권자, 축소 기한과 예외 절차가 명확해야 한다. 숫자를 산출하는 것보다 원인과 조치가 추적되는지가 중요하다.

## 백테스트의 최소 원칙

1. 전략을 만들 때 본 데이터와 최종 평가 데이터를 시간순으로 분리한다.
2. 미래 정보를 과거 시점에 사용하지 않는지 확인한다.
3. 상장폐지 종목을 제외해 성과가 좋아지는 생존편향을 경계한다.
4. 수수료, 세금, 스프레드, 시장충격과 체결 지연을 반영한다.
5. 여러 전략을 반복 시험해 가장 좋은 것만 고르는 데이터 스누핑을 통제한다.
6. 전체 기간 성과뿐 아니라 시장 국면별 성과와 최대낙폭을 확인한다.
7. 표본외 기간과 워크포워드 검증으로 재현성을 점검한다.

좋은 백테스트는 높은 수익률보다 어떤 가정에서 실패하는지를 보여 준다. 단순 보유와 같은 기준전략을 두고, 복잡성이 추가 성과를 정당화하는지 비교한다.

## RAG를 안전하게 사용하는 법

RAG는 질문과 관련된 문서 조각을 검색해 답변의 근거로 제공한다. 검색되었다고 내용이 자동으로 최신이거나 정확한 것은 아니다. 출처 문서, 절 제목, 기준일을 확인하고 검색 점수가 낮으면 질문을 더 구체적으로 바꾼다.

생성형 모델을 연결한 경우에도 문서에 없는 숫자와 결론을 만들 수 있다. 투자 의사결정에 사용할 때는 원문과 계산을 다시 확인하고, 공식 공시·규정·상품설명서와 대조한다. 민감한 개인정보와 API 키는 문서로 업로드하지 않는다.

## 최종 통합 실습

1. 관심 자산 또는 기업을 하나 선정한다.
2. 1~9단원의 체크리스트로 상품 구조, 거시환경, 재무, 가치, 산업과 포트폴리오 영향을 정리한다.
3. RAG에 질문하고 인용된 원문이 답변을 실제로 뒷받침하는지 확인한다.
4. 기준전략과 분석전략을 백테스트하고 거래비용과 표본외 성과를 비교한다.
5. 정상·낙관·위기 시나리오의 손실, 한도와 대응계획을 한 페이지로 작성한다.

## RAG 질문 예시

- VaR, Expected Shortfall, 스트레스 테스트의 역할을 비교해 줘.
- 백테스트에서 정보누수와 생존편향을 발견하는 체크리스트를 만들어 줘.
- 지금 검색한 답변이 근거 문서에 의해 뒷받침되는지 출처별로 정리해 줘.
